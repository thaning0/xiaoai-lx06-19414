# 刷写与恢复说明

## 当前状态

本项目的构建流程已经整理为可执行工具，USB 写入部分仍保留为设备专用的参考实现。

| 工具 | 用途 | 公开版状态 |
| --- | --- | --- |
| `lx06_usb_read.py` | 识别设备、读取命名分区 | 可用，见[USB 文档](windows-usb.md) |
| `lx06_usb_bank_probe.py` | 通过校准命令观察当前 boot_part | 只读研究工具 |
| `lx06_usb_flash_system1.py` | 写入 system1 并完整回读 | 命令行入口禁用，保留协议和测试 |
| `lx06_usb_select_boot1.py` | 保存 boot0→boot1 切换 | 命令行入口禁用，保留协议和测试 |

两个变更工具绑定了实测设备的备份和镜像校验值，不能直接用于其他音箱。其中 `CANDIDATE` 对应早期权限错误的镜像，`DIAGNOSTIC` 对应含设备配置的诊断 v2；这些镜像不随项目分发。保留固定校验是为了准确描述原操作的输入范围，当前没有通用的刷写命令或 `--force` 选项。

## 实测采用的写入方式

本次适配只修改 `system1`，保留设备自己的 `boot0`、`boot1` 和 `system0`。写入后读取完整 40 MiB `system1` 进行校验，并确认其他分区未变。

参考代码包含传输头、校验和、状态响应、写前检查和回读流程。USB ACK 表示命令或传输被接受，不足以证明 NAND 内容已正确保存；因此完整回读是必要步骤。

公开源码新生成的镜像尚未重新刷入硬件。需要继续开发写入工具时，应先准备以下信息：

1. 自己设备的分区布局、当前启动分区和可用恢复分区。
2. 本机逻辑分区备份、独立二次回读结果及完整环境变量快照。
3. 新镜像的构建报告、文件树检查结果，以及实际擦除范围。
4. 可以使用的 USB recovery 或 U-Boot 恢复入口。

不同 LX06 批次可能使用不同 NAND。内核、boot 分区和校准数据应来自本机，不能通过换用其他设备的镜像来补齐。

## 恢复原则

镜像恢复使用**本机对应分区的备份**，恢复后再次完整回读。读取出的 data 是逻辑分区数据，不等同于可以直接回灌的文件级备份；本项目尚未提供通用恢复程序。

`boot_part` 切换只改变启动选择，不会恢复镜像。保存环境变量也不等于恢复固件。操作前应确认被选中的 boot/system 组合本身可启动。

断电后黄灯不联网的案例通过修改一个 U-Boot 环境变量解决，无需重新刷写镜像，具体步骤及回滚见[冷启动问题处理](coldboot.md)。
