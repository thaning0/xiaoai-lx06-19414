## 实测镜像与公开源码

设备测试使用的是修复后的诊断 v2 镜像；网页随后通过 `/data` 文件、bind mount 和 `cron @reboot` 更新，断电启动后仍有效。

公开源码已将新网页直接纳入构建，并补齐构建报告校验。有界 BusyBox 日志修复和 Squeezelite 开机 opt-in 策略也直接进入当前 LX06 1.94.14 镜像；基础及诊断层均要求最终策略、启动链接和源码重放一致。这些新镜像尚未重新刷入设备。

已刷设备通过独立 `/data` runtime overlay 安装日志文件和 Squeezelite init，保留网页原有 @reboot 条目。已验证软件重启后自动加载，重复执行不叠加挂载或重启健康日志实例；短时检查未再出现 OOM，长期运行仍待观察。该部署方式需处理 cron 和 S50/S99 的竞态，与新镜像直接内置修复不同，不能据此宣称新镜像启动已经实测。

有界日志解决原厂 logger 崩溃导致的 maps/core 放大。日志恢复后，该 128 MB RAM 配置仍观察到 Squeezelite 锁住约 30 MB 内存并反复 OOM；停止后可用内存约 50 MB，API 正常。因此当前 profile 将这个可选客户端改为按需启动，保留程序和手动使用，其他音频服务不变。主动启用它或并行运行更多语音/音频服务仍需评估内存和实际播放；没有将所有 OOM 归因于日志。

本方案替换原生小爱服务，不保留原小爱语音助手和原有配网流程。
